Đo Token Và Ước Tính Chi Phí DeepSeek

Tài liệu này dùng cách đo thực tế từ DeepSeek API response. Các giá token bên dưới là giả định phục vụ demo, không phải báo giá chính thức.

Request Mẫu

Nút thanh toán trả HTTP 500 với mọi thẻ Visa từ 14:30.
Hãy triage issue và cho biết team nào cần xử lý.

Workflow hiện tại có thể gọi LLM 2 lần: lần 1 để phân loại issue trong classify(), lần 2 để yêu cầu tool call get_component_owner trong request_owner_tool_call().

Cách Đo Token Thực Tế

Sau mỗi lệnh self.client.chat.completions.create(...), đọc trường response.usage. DeepSeek Chat Completions trả prompt_tokens, completion_tokens, total_tokens, prompt_cache_hit_tokens và prompt_cache_miss_tokens.

response = self.client.chat.completions.create(
    model=self.model,
    messages=build_messages(issue),
    response_format={"type": "json_object"},
    max_tokens=500,
    **self._request_options(),
)

usage = response.usage
cache_hit_tokens = getattr(usage, "prompt_cache_hit_tokens", None) if usage else None
cache_miss_tokens = getattr(usage, "prompt_cache_miss_tokens", None) if usage else None

# Fallback cho provider OpenAI-compatible chỉ trả cached_tokens lồng trong details.
if usage and cache_hit_tokens is None:
    details = getattr(usage, "prompt_tokens_details", None)
    cache_hit_tokens = getattr(details, "cached_tokens", 0) if details else 0
if usage and cache_miss_tokens is None:
    cache_miss_tokens = usage.prompt_tokens - cache_hit_tokens

print({
    "prompt_tokens": usage.prompt_tokens if usage else None,
    "completion_tokens": usage.completion_tokens if usage else None,
    "total_tokens": usage.total_tokens if usage else None,
    "prompt_cache_hit_tokens": cache_hit_tokens,
    "prompt_cache_miss_tokens": cache_miss_tokens,
})

Lặp lại cách đọc này cho cả classify() và request_owner_tool_call(), sau đó cộng token của hai response để ra token cho một request triage hoàn chỉnh.

Công Thức

Input tokens / issue
= classify.prompt_tokens + owner_tool_call.prompt_tokens

Cached input tokens / issue
= classify.prompt_cache_hit_tokens + owner_tool_call.prompt_cache_hit_tokens

Cache miss input tokens / issue
= classify.prompt_cache_miss_tokens + owner_tool_call.prompt_cache_miss_tokens

Output tokens / issue
= classify.completion_tokens + owner_tool_call.completion_tokens

Input cost / issue
= cached_input_tokens / 1,000,000 x cache_hit_price
+ cache_miss_input_tokens / 1,000,000 x cache_miss_price

Output cost / issue
= output_tokens / 1,000,000 x output_price

Total cost / issue
= input_cost + output_cost

Monthly cost
= total_cost_per_issue x issues_per_month

Ghi Chú Về Tool Calling

Tool schema, message hệ thống, JSON output, tool call arguments và retry đều có thể làm tổng token thay đổi. Vì vậy số đo đáng tin nhất là response.usage từ request thật, không phải tokenizer offline.

POST /api/triage
  -> classify() LLM call
  -> validate JSON output
  -> request_owner_tool_call() LLM call
  -> execute get_component_owner() trong application
  -> final response

Với DeepSeek Chat Completions không streaming, usage nằm trực tiếp trong response. Nếu dùng streaming, cần bật hoặc đọc usage ở chunk cuối theo cấu hình streaming của DeepSeek. Nếu không lấy được cache fields, hãy tính bảo thủ bằng cách xem toàn bộ input là cache miss. Khi không có usage thật, mới dùng tokenizer offline làm estimate tạm thời.
